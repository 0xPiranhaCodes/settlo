# 0014 Statements and exports: pdf on device, share_plus to share

## Status
Proposed (10 Nov 2026), with Download statement and export (#108).

## Context
Loan detail's **Download statement** and Profile › **Export** produce a loan statement PDF, and a space's expenses as CSV with a summary PDF, from what the user can already see (context pack; canvas Loan and Profile). They are made on the device, so nothing new is sent to a server, and handed to the system share sheet. The Flutter SDK cannot write a PDF or open the share sheet. `share_plus` is approved by [0001](0001-stack.md); a PDF library is not, and [0005](0005-dependency-policy.md) asks for an ADR. Neither was in the lockfile.

## Decision
- **`pdf`** (`^3.13.1`, Apache-2.0) in `packages/core`. Each document is first built as a plain `Statement` (facts, totals in paise, table rows marked counted or not), and then `statementPdf` lays it out (`lib/export/`). It is pure Dart: no native code and no platform channel. It brings in `barcode` (Apache-2.0), `bidi` (MIT), `qr` (BSD-3-Clause) and `path_parsing` (MIT); `archive`, `crypto`, `image` and `xml` were already in the lockfile. The PDF embeds bundled Figtree ([0006](0006-fonts.md)), so ₹ and the type match the app and nothing is fetched.
- **`share_plus`** (`^13.3.1`, BSD-3-Clause) in `packages/platform`, behind `shareFilesProvider`, which tests override. It brings in `share_plus_platform_interface`, `cross_file` (BSD-3-Clause), `win32` and `ffi_leak_tracker` (BSD-3-Clause; Windows only, not built for iOS or Android). Exports are written as files, never in memory, to a private `exports/` folder in the app cache. That needs **`path_provider`** (`^2.1.6`, BSD-3-Clause) in `packages/platform`, which was already in the lockfile through `supabase_flutter`. Its tests fake `SharePlatform`, so `share_plus_platform_interface` is also a dev dependency of `packages/platform`; it is already in the lockfile.
- **`intl`** (`^0.20.2`, BSD-3-Clause) in `packages/core`, only for `Bidi.detectRtlDirectionality`, which picks each drawn name's direction. It was already in the lockfile, through `flutter_localizations`.
- CSV is written by hand (RFC 4180 quoting, a UTF-8 byte order mark, CRLF). It needs about 20 lines, so no `csv` package.
- **Privacy.** Exports name people, never their numbers. A member known only by number appears as `Member n`, and a loan's other party as `The other party`. In every exported name and free-text field, an Indian phone number is replaced by `••••`. That is 10 digits, optionally led by `+91`, `91` or `0`, with single spaces or hyphens allowed and no digit directly before or after. Digits in any script count (`\p{Nd}`, normalised to ASCII before matching, so Devanagari `९८०००…` is caught), and the same goes for a name made only of a number. This covers labels, the space name, descriptions, categories, references and dispute reasons. A 12-digit run in a repayment's reference is kept: that is the payer's UTR, which they need for reconciliation. Amounts and dates are built by the export itself and are left alone. A single space counts as a boundary, so a foreign number may be partly redacted; that errs towards privacy.
- **Retention.** `exports/` holds nothing but exports. Each export writes to its own `exports/share-<random>/` folder (`Directory.createTemp`), which is deleted when that share completes, is dismissed or fails. A second export while the first share sheet is open never touches the first one's files. The whole folder is cleared at app start, awaited before `runApp`, when no share can be active; it is never cleared mid-session.
- **Scripts the PDF fonts cannot draw.** The `pdf` package does not shape complex scripts, and Figtree has no Indic glyphs. So any text run the bundled font cannot cover, such as a Devanagari name, is laid out by Flutter's text engine on the UI isolate (`TextPainter`, which shapes it correctly). Its direction comes from `intl`'s bidi detection, so Urdu is laid out right to left. It is saved as a PNG at four times 10pt, with its measured alphabetic baseline, and placed inline at the text's size, shifted so its baseline sits on the row's text baseline. If drawing fails, the PDF shows `Name in another script`. The CSV always keeps the real text.
- **Off the UI isolate.** The CSV is streamed to its file line by line, and the PDF bytes are built in `Isolate.run`. The isolate gets plain data: the ledger, the `Statement`, the font bytes and the name images drawn beforehand. A 5,000-expense space is tested for page breaks and an unblocked UI isolate.

## Alternatives considered
- **`printing`** (same author as `pdf`). Its share and print sheet and its rasteriser need native plugins (pdfium on some platforms), and share_plus is already approved.
- **`syncfusion_flutter_pdf`.** Commercial licence terms.
- **Rendering with Flutter and saving an image.** The PDF would have no selectable text, and amounts could not be searched or copied.
- **Server-side generation (Edge Function).** It would send ledgers off the device, and would not work offline.

## Consequences
- 10 new packages in the lockfile. `pdf` adds roughly 1 MB of Dart to the app before tree shaking; share_plus adds a small native plugin on iOS and Android.
- **Tests check the `Statement`, not the rendered PDF:** rows, totals and disputed exclusion in paise, the IST stamp, and names only. A smoke test checks that the bytes are a PDF with the expected page count. The ubuntu-24.04 runner has no PDF rasteriser, and CI gets no new system packages, so there is no golden of a rendered page. Adding `poppler-utils` to CI would allow one later.
- A name drawn as an image cannot be selected or searched in the PDF; amounts and Latin text still can. The image always prints in the ink colour, even in a muted row.
- Tests register Noto Sans Devanagari and Noto Naskh Arabic (OFL 1.1, `app/test/fonts/` with their notices, test only, never app assets), because the test engine has no system fonts. Linux goldens of a Devanagari and an Urdu name then show real shaping. Tamil, Bengali, emoji and mixed names are checked for size and baseline only, since the test engine has no font for them.
